# Процесс запуска интерпретатора

в режиме сборки под Linux:

- [[cmake/CMake|cmake]]
	```sh
	$ cmake --fresh --preset linux
	$ cmake --build --preset linux -j
	```
- `bin/bcx`
	- первый параметр в командной строке: `lib/bcx.ini`
	- опционально: другие файлы с расширениями `*.ini` `*.f`
- компиляция стартового байткода в память виртуальной машины:
	- парсер: `src/bcx.ragel` (неудобно, не используем)
		- простая регулярная грамматика: достаточна для языка Форт
		- [[ragel]] генерирует конечный автомат на Си
	- применение классической пары [[syntax/flex|flex]] + [[syntax/bison|bison]]
		- `src/bcx.lex` + `src/bcx.yacc`
		- даёт более широкие классы грамматик, подходящих в том числе для embedded-диалектов высокоуровневых языков
		- лучше совместима с POSIX file I/O
	- в отличие от большинства форт-систем, [[bcx]] стартует с совершенно пустой памятью байт-кода, словаря/таблицы символов
		- референсная реализация форт-системы поставляется в виде исходных кодов, что позволяет вам
			- полностью заменить Форт своим кодом
			- исследовать и свободно модифицировать внутренности базовой системы
- после компиляции байт-кода запускается [[FVM]]:
	- виртуальная форт-машина = интерпретатор байт-кода
	- `HOST`:
		- виртуальная машина на рабочей станции разработчика или сервере
		- HOST triplet: условная строка, указывающая на тип целевой платформы, операционной системы и иногда процессора
			- [[x86_64-linux-gnu]]: ноутбук/ПК на Linux
			- [[x86_64-linux-musl]]: docket-контейнер
			- [[aarch64-linux-gnu]]: для тех кто экспериментирует с [[Raspberry Pi]] в качестве головного устройства разработки
			- [[i686-w64-mingw32]]: для странных случаев, когда вы почему-то хотите использовать ретрокомпьютер на 32-битном [[Windows#XP]] или даже [[Windows#2000]] (для ещё более старых систем можно применить [[OpenWatcom]])
			- [[x86_64-w64-mingw32]]: 64-битный вариант Windows (не поддерживается пока хватает более универсальных 32-битных сборок)
- в зависимости от содержимого кода инициализации
	- `TARGET`: другие устройства или сервера, для которых планируется разрабатывать ПО
		- TARGET triplet:
			- [[arm-none-eabi]]: микроконтроллеры семейств [[em/Cortex-M|Cortex-M]] (в основном STM32 и то что есть в [[QEMU#ARM]])
			- [[xtensa]]: [[ESP32-S]]/[[LX6]] (дёшево, популярно, беспроводные сети)
			- [[RiscV]]/[[ESP32-C]] (дорого, но есть интересные устройства с мини[[TFT]]/[[e-Ink]] экранчиками)
			- [[i386-linux-uclibc]]: embedded Linux и ретрокомпьютеры
	- выполняется поиск устройств, подключенных через USB/serial, RS485, RS232, Ethernet, WiFi, BT/serial, и находящихся в режиме запуска (сторонней инициализации)
	- на найденные устройства отсылается копия базовой Форт-системы в виде бинарного образа уже скомпилированного байт-кода,
	- или отправляются файлы инициализации (те же, что и при старте хост-форта, или специальные с кодом для каждого найденного устройства)
	- для каждого устройства выполняются специфичные для него команды настройки, в том числе сохранение байткода в энергонезависимую память и запуск режима выполнения после рестарта
- для некоторых целевых платформ при желании можно добавить поддержку прошивки и отладки через аппаратный отладчик или последовательный порт: [[STM32]]/`libstlink-dev`, 
	- для некоторых платформ опубликованы протоколы прошивки/отладки, поэтому для них можно также написать свою реализацию протокола вместо использования OpenSource библиотек: `esp-serial`,..
	- возможен прямой аппаратный доступ к памяти и периферии, а также автоматическая предпрошивка пустых чипов интерпретатором `bcx`
