# Лексер

`src/bcx.lex`

```cpp
%{
    #include "app.hpp"
    char *yyfile = nullptr; // current file name
%}

%option noyywrap yylineno

%%
.           {yyerror("");}  // syntax error on any undetected char
```
- любой Си-код между скобками `%{%}` копируется в `.lex.cpp` как есть
- `noyywrap` отключает механизм множественных файловых буферов. 
	- функция `yywrap()` вызывается при достижении конца файла и может переключить ввод на другой файл. В нашем случае мы не нуждаемся в такой функциональности.
- для вывода диагностики ошибок:
	- `yyfile` хранит текущее имя файла
	- `yylineno` включить автоматический подсчёт текущей строки в лексере
	- `.` сработает на **любой символ**, который не был распознан предыдущими правилами

```cpp
void yyerror(std::string msg) {
    std::cerr << "\n\n"
              << yyfile << ':' << yylineno << ' ' << msg << " [" << yytext
              << "]\n\n";
    exit(-1);
}
```

Первая часть любого компилятора или интерпретатора — лексический анализ. Исходный текст, понятный человеку, состоит от из отдельных символов, хранящихся в файле, или полученные в строке ввода команды.

Его нужно превратить в поток токенов: типизованных кирпичиков, с которыми уже может работать синтаксический анализатор при определении грамматики языка, и разборе исходного кода (команд).

Представьте себе поток символов: `: MAX ( a b -- max ) 2DUP < IF SWAP THEN DROP ;`. Для человеческого глаза это осмысленная строка на языке Форт, определяющая новое слово `MAX`. Для компьютера, а точнее, для последующих этапов компиляции, это просто длинная цепочка байт.

Токен:

- **тип токена**: `COLON` `ID` `NUMBER` `WORD` `IF` ...
- **значение токена** (не обязательно): `:` `name` `+1234` `"строка"` ...
- опционально: ссылка на имя файла, и строка/столбец для локализации токена при обработке синтактических ошибок

Также лексер позволяет сразу вырезать комментарии и незначащие пробельные символы:

```cpp
#![^\n]*    {}              // shebang
\\[^\n]*    {}              // line comment
[ \t\r\n]+  {}              // drop spaces
```

Список токенов определяется в файле `.yacc` как **терминалы** в определении грамматики: атомарные, неделимые единицы языка представляющие имена, числа, операторы, строки.. Терминал в грамматике языка не может быть разобран на составляющие.

```cpp
%defines %union { char c; int n; }
%token COLON SEMICOLON
```
- `%defines` включает создание файла `bcx.yacc.hpp` с именами токенов
	- его нужно включить в `bcx.lexer.cpp`
- `%union` задаёт типы параметров для токенов со значениями
- `%token` задаёт токены без значений

```cpp
:           {return COLON    ;}  // маркирует адрес метки (нового слова)
;           {return SEMICOLON;}  // завершает определение слова
```
