# JavaScript или его встраиваемый диалект

JavaScript прочно обосновался в мире интернета вещей благодаря таким платформам, как Espruino или JerryScript. Фронтенд для JavaScript должен будет работать с его прототипным наследованием, асинхронностью и динамической типизацией. Сложность здесь в том, чтобы эффективно отобразить динамическую природу языка на статическую модель памяти `bcx`.

Каждое значение в JavaScript — это объект со сложным поведением. В статической памяти `bcx` мы можем представить JavaScript-значение как дескриптор (handle) — указатель на структуру в куче, где хранится информация о типе и сами данные. Арифметические операции потребуют проверки типов во время выполнения: если программист написал `a + b`, интерпретатор должен сначала проверить, являются ли `a` и `b` числами, и только потом выполнить сложение, либо, если это строки, выполнить конкатенацию.

Объекты и прототипное наследование реализуются через цепочки поиска свойств в хеш-таблицах.

Безусловно, потребуется реализации сборщика мусора на уровне виртуальной машины, чтобы автоматически освобождать память, занятую объектами, на которые больше нет ссылок.

JS-фронтенд будет самым тяжелым, но он откроет дверь в мир `bcx` для огромной армии JavaScript-разработчиков.
