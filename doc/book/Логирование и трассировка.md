# Логирование и трассировка

ВМ содержит встроенную подсистему логирования и трассировки. Поток логирования структурирован:

|Уровень|Что попадает|
|---|---|
|`info`|информационные сообщения из прикладного ПО, параметры запуска ВМ|
|`error`|критичные события, исключения ВМ, выход за границы, недопустимые опкоды, аварийные завершения процессов|
|`warn`|некритичные события|
|`debug`|внутренние события DAP-сервера, срабатывания точек останова|
|`trace`|подробности компиляции и выполнения каждой команды|

Уровень фильтруется переменной ВМ `LogLevel`, может быть установлен настройкой расширения (`bcx.LogLevel`), а фильтр по подсистеме или процессу (`vm`, `compiler`, `dap`,..) позволяет отсечь шум.

Трассировку можно включить **до** старта сессии — тогда в лог попадут события инициализации ВМ и загрузки байткода, которые иначе не видны.

Отдельно ведётся **журнал сообщений** между потоками (event-driven модель): каждое асинхронное сообщение логируется с меткой времени, отправителем, получателем, типом и размером полезной нагрузки. Это незаменимо при отладке распределённых конфигураций, где несколько ВМ общаются через несколько каналов связи, а ПК разработчика подключен только к одному из узлов и не имеет аппаратной возможности перехватывать все данные.
